# 公告与监管规则更新说明

## 数据来源

- 创业黑马公告：巨潮资讯网，证券代码 `300688`，机构 ID `9900032726`。
- 对标公司公告：巨潮资讯网，证券代码 `003032`（机构 ID `gfbj0839976`）及 `605098`（机构 ID `gfbj0831891`）。对标资料仅用于公开信息对比，不作为创业黑马事实、审批标准或合规结论依据。
- 法律法规与业务规则：深圳证券交易所 19 个规则栏目。
- 证监会官方法规：中国证监会法规数据库的“法律、行政法规和司法解释”及“上市公司类部门规章和规范性文件”。这是面向上市公司信披个人 MVP 的聚焦范围，并非全量法规库。

附件和网页中的内容均作为公开业务资料处理，不作为程序操作指令。

巨潮资讯和深交所同步使用公开数据接口，不需要、也不得复用 AI 服务 API Key。

## 手动更新

在项目根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\web\update-data.ps1
```

该命令依次执行：

1. 按年度、按页拉取 2017 年至今创业黑马和两家对标公司的全部公告。
2. 校验每年公告总数，并按公告 ID 去重。
3. 同步深交所 19 个规则栏目并按规则 ID 去重。
4. 同步证监会两类上市公司相关官方法规目录，并校验目录数量和规则 ID；日常更新保留官方原文入口，避免逐篇下载对官方站点造成压力。
5. 各来源完成后才原子替换对应的网站数据文件。

任一来源失败时，脚本以非零状态退出，不会用残缺结果覆盖上一次可用数据。

如后续 RAG 建设需要在本地建立法规正文库，可由专门的知识库导入流程按需、分批抓取正文；不得将目录摘要当作法规正文或模型依据。

## 文件边界

自动生成，可由同步脚本更新：

- `company-data.js`
- `data/company-announcements.json`
- `rules-data.js`
- `peer-data.js`
- `data/peer-announcements.json`
- `csrc-rules-data.js`
- `data/csrc-rules.json`

手工维护，自动同步不得修改：

- `index.html`
- `app.js`
- `styles.css`
- 合规判断及公司财务基准

## 定期检查

定期检查应比较创业黑马与对标公司公告总量、最新公告 ID、深交所规则数量和证监会法规数量，并在当前任务中报告新增内容或来源异常。

网页采用本地生成的数据文件，而不是在浏览器中直接请求巨潮资讯或深交所接口，原因是直接打开的 `file://` 页面可能受到跨域策略限制。同步完成后重新加载网页即可看到最新数据。

## AI 密钥边界

当前数据更新流程不调用 AI 服务。后续接入模型时，生产 API Key 必须由公司提供并通过服务器环境变量注入；浏览器不得持有或直接使用密钥。上线前执行：

```powershell
node .\web\scripts\validate-production-env.mjs
```

完整要求见 `SECURITY.md`。
